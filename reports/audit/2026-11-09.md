## 3. Evidence-Backed Findings Audit

### Finding FR-DATA-002: Concurrent Race Condition in Active Rule Version Validation
1. **ID and Severity**: `FR-DATA-002` | **MEDIUM**
2. **Category**: Data Integrity / Concurrency
3. **Location**: `flexirule/ruleflow/doctype/rule/rule.py:1874-1896` (`validate_single_active_version`)
4. **Evidence**: `validate_single_active_version` checks for an existing active version using `frappe.get_all("Rule", filters={"base_rule_name": self.base_rule_name, "is_active": 1, "name": ["!=", self.name]}, pluck="name", limit=1)`. This is a non-locking `SELECT` query. If two concurrent transactions activate different versions of the same logical rule lineage simultaneously, both can pass the check before committing, resulting in multiple active versions for one logical rule.
5. **Impact**: Multiple active versions in the database break deterministic rule resolution by `RuleCoordinator`, causing inconsistent execution paths across workers.
6. **Root Cause**: Reliance on read-committed `frappe.get_all` without transactional row locking (`FOR UPDATE`).
7. **Native Frappe Alternative**: Native Frappe Query Builder with locking:
   ```python
   rule = frappe.qb.DocType("Rule")
   existing_active = (
       frappe.qb.from_(rule)
       .select(rule.name)
       .where((rule.base_rule_name == self.base_rule_name) & (rule.is_active == 1) & (rule.name != self.name))
       .for_update()
       .run(as_dict=True)
   )
   ```
8. **Version Compatibility**: Frappe v15 & v16 (`frappe.qb` supports `.for_update()` on MariaDB/PostgreSQL).
9. **Recommendation**: Replace `frappe.get_all` with `frappe.qb` using `.for_update()` in `validate_single_active_version`.
10. **Tests**: Add concurrent activation test in `flexirule/ruleflow/tests/test_rule_versioning.py`.
11. **Confidence**: Confirmed (Open).

### Finding FR-SEC-004: Background Task User Context Degradation
1. **ID and Severity**: `FR-SEC-004` | **HIGH**
2. **Category**: Security / Authorization
3. **Location**: `flexirule/ruleflow/core/permissions.py:160-185` (`can_ignore_permissions`)
4. **Evidence**: In background job executions (e.g. queue workers), `frappe.session.user` defaults to `"Administrator"`. Because `can_ignore_permissions` checks `if user != "Administrator" and not user_roles.intersection(allowed_roles):`, all background tasks automatically bypass the role gate even if initiated by an unprivileged user.
5. **Impact**: Unprivileged users scheduling background rules or triggers can execute privileged mutations without required authorization checks.
6. **Root Cause**: `frappe.session.user` is inspected directly instead of capturing and propagating the triggering user context (`context.user`).
7. **Native Frappe Alternative**: Check `context.get("user") or frappe.session.user` and enforce role resolution against the originating execution user.
8. **Version Compatibility**: Frappe v15 & v16.
9. **Recommendation**: Update `can_ignore_permissions` to accept explicit `user` argument defaulted from `context.get("user")` and check roles for that user via `frappe.get_roles(user)`.
10. **Tests**: Existing suite in `test_permissions.py` should be expanded to simulate worker execution with non-admin context.
11. **Confidence**: Confirmed (Open).

### Finding FR-PERF-001: N+1 Query & Validation Overhead in Child Table Appends
1. **ID and Severity**: `FR-PERF-001` | **HIGH**
2. **Category**: Performance
3. **Location**: `flexirule/ruleflow/core/action_handlers/document_action.py:530-580` (`_apply_table_mappings`)
4. **Evidence**: Iterates over row items and calls `doc.append(table_field, row_payload)` individually for each mapped row.
5. **Impact**: In large batches or child tables with 100+ rows, each `doc.append()` triggers schema lookups and initialization hooks, multiplying memory and CPU consumption.
6. **Root Cause**: Sequential append loop without batch assignment.
7. **Native Frappe Alternative**: Construct row payload list and assign in bulk:
   ```python
   if reset_value:
       doc.set(table_field, accumulated_rows)
   else:
       doc.extend(table_field, accumulated_rows)
   ```
8. **Version Compatibility**: Frappe v15 & v16 (`doc.extend()` and `doc.set()` supported across all releases).
9. **Recommendation**: Refactor `_apply_table_mappings` to accumulate rows into a list and apply via bulk assignment.
10. **Tests**: Benchmark child table action execution in `test_document_action.py`.
11. **Confidence**: Confirmed (Open).

### Finding FR-FE-002: Double JSON Serialization Contract Mismatch
1. **ID and Severity**: `FR-FE-002` | **MEDIUM**
2. **Category**: Frontend / Serialization Contract
3. **Location**: `flexirule/public/js/flexirule/rule_builder/stores/useRuleStore.js:460-488`
4. **Evidence**: `serializeField` applies `JSON.stringify()` to action configs, condition JSON, and resolved schemas. When saving via `frappe.call("frappe.client.save")`, Frappe client serialization may double-escape JSON string values if fields are typed as `JSON` or `Code`.
5. **Impact**: Redundant string escapes in stored documents require nested parsing handling on backend.
6. **Root Cause**: Frontend store serializes all object fields to string without checking whether Frappe client layer handles dictionary fields directly.
7. **Native Frappe Alternative**: Rely on native Frappe DocType `JSON` field type parsing.
8. **Version Compatibility**: Client-side JS / Frappe v15 & v16.
9. **Recommendation**: Harmonize `serializeField` to preserve raw objects for DocType fields declared as `JSON`.
10. **Tests**: `tests/frontend/flexirule/rule_builder/utils/stable_serialization.test.mjs`.
11. **Confidence**: Confirmed (Open).

## 4. Native Frappe Framework API Comparison Matrix

| Area | FlexiRule Implementation | Native Frappe Alternative | Recommendation & Architectural Decision |
| :--- | :--- | :--- | :--- |
| **Active Version Locking** | `frappe.get_all("Rule", ...)` (non-locking) | `frappe.qb.from_(Rule).for_update()` | **Adopt Native**: Switch to `frappe.qb` with `.for_update()` to enforce transactional serialization on active version validation. |
| **Workspace Custom Docs** | `hide_custom: 1` in `ruleflow.json` | Frappe `hide_custom` DocField | **Leverage Native**: Cleanly prevents custom doctypes from leaking into module workspace navigation. |
| **Child Table Bulk Appends** | Loop with `doc.append()` | `doc.extend(field, rows)` / `doc.set()` | **Adopt Native**: Batch rows into single assignment call to eliminate repeated child meta lookups. |
| **AST Sandbox Visitor** | Custom `SafeEvalVisitor` | `frappe.safe_eval()` | **Retain Custom**: Retain explicit AST inspection for dunder attributes; native `frappe.safe_eval()` introduces RestrictedPython bytecode overhead. |
| **Action Plan Cache** | Direct Redis pattern clearing | `frappe.cache.delete_keys()` | **Leverage Native**: Native CacheManager guarantees compatibility across standalone and clustered Redis setups. |
