## 2. Operational Status of Daily Scheduled Jules Audit

### Automation Mechanism
The daily scheduled audit is configured in `.github/workflows/jules-task.yml` using GitHub Actions `schedule` with cron expression `0 2 * * *` (02:00 UTC daily).

### Execution Flow
1. **Trigger**: GitHub Actions triggers `.github/workflows/jules-task.yml` on cron `0 2 * * *` targeting branch `develop`.
2. **Branch & Prompt Verification**: The Python step validates `develop` branch existence via GitHub REST API and prepares the JSON payload targeting `sources/github/Sendipad/flexirule`.
3. **Jules Session Creation**: The workflow sends a `POST` request to `https://jules.googleapis.com/v1alpha/sessions` authenticating via `secrets.JULES_API_KEY`.
4. **Autonomous Execution**: Jules executes the daily audit on `develop`, runs test suites, builds audit findings, and creates an audit PR or summary.

### Requirements & Required Configuration
- **Secret Requirement**: `secrets.JULES_API_KEY` must be populated in the GitHub repository secrets settings.
- **Blocker Status**: If `JULES_API_KEY` is missing, job step `Create Jules session` exits with code 1 and outputs `::error::The JULES_API_KEY repository secret is not configured.`

## 3. Evidence-Backed Findings (11 Required Fields Each)

### Finding FR-SEC-001: AST Validation Stub in `validate_safe_eval`
1. **ID and Severity**: `FR-SEC-001` | **CRITICAL**
2. **Category**: Security
3. **Location**: `flexirule/ruleflow/core/permissions.py:186-215` (`SafeEvalVisitor`)
4. **Evidence**: `SafeEvalVisitor` inspects `ast.Attribute` and `ast.Name` nodes to throw `ValidationError` on dunder attribute accesses (`__class__`, `__mro__`, `__subclasses__`) and prohibits `Import` / `ImportFrom` nodes.
5. **Impact**: Prevents Python sandbox escapes and arbitrary code execution through expression evaluation in condition rules.
6. **Root Cause**: Earlier versions used `compile()` syntax check without inspecting AST nodes.
7. **Native Frappe Alternative**: `frappe.safe_eval()` with RestrictedPython, combined with custom AST visitor for domain-specific context.
8. **Version Compatibility**: Frappe v15 / v16 (`ast` built-in Python module).
9. **Recommendation**: Retain current `SafeEvalVisitor(ast.NodeVisitor)` pattern as a pre-eval validator before evaluation.
10. **Tests**: Covered by `test_FR_SEC_001_ast_validation_stub_sandbox_escape` in `test_permissions.py`.
11. **Confidence**: Confirmed (Fixed & Verified).

### Finding FR-SEC-002: Server-Side Template Injection in Document Action Rendering
1. **ID and Severity**: `FR-SEC-002` | **CRITICAL**
2. **Category**: Security
3. **Location**: `flexirule/ruleflow/core/action_handlers/document_action.py:642-660` (`_render_scalar`)
4. **Evidence**: `_render_scalar` constructs Jinja rendering contexts containing only `doc` and `vars`, strictly stripping `frappe` module access from context globals.
5. **Impact**: Prevents Server-Side Template Injection (SSTI) through user-supplied Jinja expression fields.
6. **Root Cause**: Template contexts previously included global `frappe` object which allowed calling `frappe.db.sql` or system methods from Jinja.
7. **Native Frappe Alternative**: `frappe.render_template(template, context, is_safe=True)`.
8. **Version Compatibility**: Frappe v15 / v16.
9. **Recommendation**: Maintain strict Jinja context sanitization.
10. **Tests**: Covered by `test_FR_SEC_002_ssti_in_document_action_rendering`.
11. **Confidence**: Confirmed (Fixed & Verified).

### Finding FR-SEC-003: SafeFrappeAPI Format Value Dict Override

### Finding FR-SEC-004: Background Task Session User Escalation
1. **ID and Severity**: `FR-SEC-004` | **HIGH**
2. **Category**: Security
3. **Location**: `flexirule/ruleflow/core/permissions.py:136-160` (`can_ignore_permissions`)

### Finding FR-DATA-001: Savepoint Rollback Failure Swallowing
1. **ID and Severity**: `FR-DATA-001` | **HIGH**
2. **Category**: Data Integrity
3. **Location**: `flexirule/ruleflow/core/engine.py:530-555` (`_execute_graph`)
4. **Evidence**: Engine wraps action node execution in `frappe.db.savepoint()`. If savepoint rollback fails, a full `frappe.db.rollback()` is invoked as fallback to prevent partial mutations.
5. **Impact**: Ensures atomic rule execution and prevents partial row updates in database transactions when errors occur mid-flow.
6. **Root Cause**: Previously, exceptions during savepoint rollback were caught without full transaction rollback, leaving partial mutations committed.
7. **Native Frappe Alternative**: `frappe.db.savepoint("flexirule_node")` and `frappe.db.rollback(save_point="flexirule_node")`.
8. **Version Compatibility**: Frappe v15 / v16.
9. **Recommendation**: Keep the `frappe.db.rollback()` fallback inside exception handlers.
10. **Tests**: `test_data_integrity.py`.
11. **Confidence**: Confirmed (Fixed & Verified).

### Finding FR-DATA-002: Concurrent Rule Activation Without Row Locking
1. **ID and Severity**: `FR-DATA-002` | **MEDIUM**
2. **Category**: Data Integrity
3. **Location**: `flexirule/ruleflow/doctype/rule/rule.py:1876-1910` (`validate_single_active_version`)
4. **Evidence**: `validate_single_active_version` executes `frappe.get_all("Rule", filters={"base_rule_name": self.base_rule_name, "is_active": 1, "name": ["!=", self.name]}, limit=1)`. This query does not request row locks (`FOR UPDATE`).
5. **Impact**: Under high concurrency or race conditions during simultaneous rule version saves, two versions of the same rule lineage can both be set to active.
6. **Root Cause**: `frappe.get_all()` executes standard `SELECT` without `.for_update()`.
7. **Native Frappe Alternative**: `frappe.qb.from_("tabRule").select("name").where(...).for_update().run(pluck=True)`.
8. **Version Compatibility**: Frappe v15 / v16 Query Builder.
9. **Recommendation**: Replace `frappe.get_all` in `validate_single_active_version` with `frappe.qb` using `.for_update()`.
10. **Tests**: Add unit test simulating concurrent activation validation.
11. **Confidence**: Confirmed (Open).

### Finding FR-ENGINE-002: Sub-Rule Recursion Depth Counter Loss
1. **ID and Severity**: `FR-ENGINE-002` | **HIGH**
2. **Category**: Correctness / Rule Engine
3. **Location**: `flexirule/ruleflow/core/action_handlers/sub_rule.py:85-110` (`SubRuleHandler.execute`)
4. **Evidence**: `SubRuleHandler.execute` increments `_sub_rule_depth = context.get("_sub_rule_depth", 0) + 1` and propagates it into child execution context, throwing `CycleDetectedError` when depth exceeds `MAX_SUB_RULE_DEPTH = 2`.

6. **Root Cause**: Sub-rule depth was previously not passed down into child contexts, causing depth counters to reset to 0 at each level.
7. **Native Frappe Alternative**: Standard Python recursion context pattern.
8. **Version Compatibility**: Frappe v15 / v16.
9. **Recommendation**: Retain explicit recursion depth tracking.
10. **Tests**: Verified by `test_FR_ENGINE_002_sub_rule_recursion_depth_propagated`.

### Finding FR-PERF-001: N+1 Query Pattern in Child Table Appends
1. **ID and Severity**: `FR-PERF-001` | **HIGH**
2. **Category**: Performance
3. **Location**: `flexirule/ruleflow/core/action_handlers/document_action.py:480-584` (`_apply_table_mappings`)
4. **Evidence**: Iterates over row items calling `doc.append(table_field, row_payload)` individually.
5. **Impact**: For child tables with hundreds of rows, individual row validation and schema lookups introduce high CPU and DB overhead.
6. **Root Cause**: `Document.append()` triggers row-level meta resolution on each call.
7. **Native Frappe Alternative**: Batch payload preparation into a single list assign (`doc.set(table_field, row_list)`) or optimized child table bulk extend.
8. **Version Compatibility**: Frappe v15 / v16.
9. **Recommendation**: Construct list of child dict payloads and populate via single `doc.extend()` or `doc.set()`.
10. **Tests**: Benchmark tests in `test_document_action.py`.
11. **Confidence**: Confirmed (Documented / Open).

## 4. Native Frappe Framework API Comparison Matrix

| Area | FlexiRule Custom Implementation | Native Frappe Alternative | Recommendation & Decision |
| :--- | :--- | :--- | :--- |
| **Expression AST Validation** | Custom `SafeEvalVisitor(ast.NodeVisitor)` | `frappe.safe_eval()` | **Retain Custom**: Native `safe_eval` uses RestrictedPython which alters execution semantics; custom AST visitor provides domain-specific dunder and import security without execution overhead. |
| **Active Version Locking** | `frappe.get_all("Rule", filters=...)` without lock | `frappe.qb.from_("tabRule").where(...).for_update()` | **Adopt Native**: Replace `frappe.get_all` in `validate_single_active_version` with Query Builder `.for_update()` to prevent concurrent active rule race conditions. |
| **Action Plan Caching** | Redis key pattern deletion | `frappe.cache.delete_value()` / `delete_keys()` | **Adopt Native**: Standardized on native Frappe CacheManager API to ensure compatibility with Redis cluster environments. |
| **Jinja Context Sanitization** | Manual dictionary context stripping in `_render_scalar` | `frappe.render_template(..., is_safe=True)` | **Retain Custom Context**: Explicit context scope (`doc` and `vars`) guarantees SSTI protection across all Jinja evaluation points. |
| **Child Table Appends** | Sequential `doc.append()` loop | `doc.set(table_field, row_list)` | **Adopt Native**: Batch child table row payloads into a single `doc.set()` call to eliminate N+1 metadata resolution calls. |
