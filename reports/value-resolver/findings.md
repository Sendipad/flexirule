# Findings & Audit Issues

This section details all specific findings identified during the Value Resolver codebase audit.

---

### VR-AUDIT-001 — Security Level Restrictions (`resolverLevel`) Enforced in UI Only

- **Severity**: High
- **Area**: Security / Backend
- **Evidence**:
  - `flexirule/public/js/flexirule/rule_builder/controls/FlexValueControl.vue` (lines 510-560): Defines `RESOLVER_LEVEL_KIND_MAP` and filters `allowedBuilderKinds`.
  - `flexirule/ruleflow/core/value_resolver.py`: `ValueResolver.compile()` and `compile_resolver_config()` do NOT inspect rule settings or context to check `resolverLevel`.
- **Problem**:
  - The site-wide setting `value_resolver_level` (e.g. set to `basic` or `standard`) is only enforced when rendering the Vue UI builder.
- **Impact**:
  - A user or external API caller can craft a Rule Action payload containing an `advanced` resolver (such as `math_formula` or `child_aggregation`) on a system configured for `basic` resolver level, and the backend engine will execute it without restriction.
- **Reproduction Scenario**:
  1. Configure `value_resolver_level = "basic"` in RuleFlow Settings.
  2. Perform a direct API request or MariaDB update on a `Rule Action` setting its assignment payload to `{ "mode": "resolver", "config": { "kind": "math_formula", "field_a": "doc.amount", "math_op": "*", "constant_b": 10 } }`.
  3. Execute the rule.
  4. The engine executes `MathFormulaResolver` successfully despite `math_formula` being disallowed at `basic` level.
- **Recommended Remediation**:
  - Pass rule context / settings into `ValueResolver.compile(val, settings=None)`.
  - Validate `config["kind"]` against `RESOLVER_LEVEL_KIND_MAP` in `compile_resolver_config()`, raising `PermissionError` or throwing a validation exception if disallowed.

### VR-AUDIT-002 — Manual Token Editing Strips Config & Forces Uncompiled `SafeEvalResolver`

- **Severity**: Medium
- **Area**: Frontend / Contract
- **Evidence**:
  - `flexirule/public/js/flexirule/rule_builder/controls/FlexValueControl.vue` (line 890):
    `if (isManualMode.value) { tokenDraftAttrs.value.config = null; }`
- **Problem**:
  - Switching to Manual Mode in the token editor modal clears the `config` object (`config = null`).
- **Impact**:
  - Stripping `config` makes it impossible to re-open the token in Visual Builder mode later.
  - Forces backend evaluation to fall back to `SafeEvalResolver` parsing string expressions instead of using pre-compiled, optimized strategy classes.
- **Reproduction Scenario**:
  1. Create a `date_formula` resolver token in `FlexValueControl`.
  2. Click the token to open the Token Modal.
  3. Switch to "Manual" mode and tweak the expression text.
  4. Save.
  5. Click the token again: Visual Builder mode is disabled because `config` is missing.
- **Recommended Remediation**:
  - Preserve `config` when switching to Manual mode if the manual expression still conforms to the strategy's compiled expression pattern, or store a flag `{ mode: "manual", raw_expression: "..." }`.

### VR-AUDIT-003 — Parameter Default Inconsistencies Between JS and Python Strategies

- **Severity**: Low
- **Area**: Contract
- **Evidence**:
  - `FlexValueControl.vue` / `value_resolver/index.js`:
    - `MathFormulaResolver` JS default: `precision = 2`, `field_b_type = "field"`.
    - `DateFormulaResolver` JS default: `base_type` defaults to `doc_field` if field context exists, otherwise `today`.
  - `value_resolver.py`:
    - `DateFormulaResolver` Python default: `base_type` defaults unconditionally to `"today"`.
    - `DateDiffResolver` Python default: `diff_end_type` defaults to `"doc_field"`.
- **Problem**:
  - If a frontend payload omits optional properties (e.g. `base_type`), the backend default differs from the UI default.
- **Impact**:
  - Inconsistent runtime behavior if partial JSON configs are sent by custom scripts or background jobs.
- **Reproduction Scenario**:
  1. Send `{ "kind": "date_formula", "base_field": "posting_date", "offset_value": 5, "offset_unit": "days" }` without `base_type`.
  2. Frontend expects `base_type = "doc_field"`.
  3. Backend defaults `base_type = "today"`, calculating 5 days from current date instead of `posting_date`.
- **Recommended Remediation**:
  - Standardize all parameter defaults in both JS strategy definitions (`defaultState`) and Python `__init__` constructors.

### VR-AUDIT-004 — Redundant `link_source_type` Field Generated in Fetch Strategy

- **Severity**: Low
- **Area**: Frontend / Payload Optimization
- **Evidence**:
  - `flexirule/public/js/flexirule/rule_builder/controls/value_resolver/index.js`: `fetch` default state includes `link_source_type: "doc_field"`.
  - `flexirule/ruleflow/core/value_resolver.py`: `FetchResolver` constructor accepts `link_field`, `fetch_field`, and `linked_doctype`.
- **Problem**:
  - `link_source_type` is generated by the frontend but ignored by the backend constructor.
- **Impact**:
  - Unnecessary payload verbosity.
- **Recommended Remediation**:
  - Remove `link_source_type` from `FetchResolver` default state or consume it in Python if dynamic link sources are added in future.

### VR-AUDIT-005 — Missing Cypress UI Coverage for Token Modal Workflows

- **Severity**: Low
- **Area**: Testing
- **Evidence**:
  - `cypress/integration/rule_builder.js` exercises canvas and action configuration but does not open the Token Configuration Modal or interact with `/` slash commands.
- **Problem**:
  - End-to-end user interactions with `FlexValueControl` token modal rely on manual testing.
- **Impact**:
  - Regression risk during UI refactoring.
- **Recommended Remediation**:
  - Add Cypress test cases in `cypress/integration/rule_builder.js` that insert a resolver token, open the modal, switch strategies, and save.

### VR-AUDIT-006 — Dual Legacy Mode Alias Handling Logic Across Codebase

- **Severity**: Medium
- **Area**: Maintenance / Tech Debt
- **Evidence**:
  - `FlexValueControl.vue` coercer handles `mode: "formula"`, `"format"`, `"normalize"`, `"normalization"`.
  - `value_resolver.py` `compile()` handles `mode in ("resolver", "formatter", "normalize", "format", "normalization")`.
  - `AssignmentHandler._compile_structured_value_to_jinja()` has a separate coercer logic.
- **Problem**:
  - Legacy mode coercion is duplicated across multiple components with slight differences in alias names.
- **Impact**:
  - Future changes to mode coercion risk breaking legacy rules if all locations are not updated synchronously.
- **Recommended Remediation**:
  - Consolidate legacy mode conversion into a single shared utility in Python (`ValueResolver.normalize_payload()`) and JS (`coerceStructuredValue()`).
